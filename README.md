# docker-compose-wp-duplicate

Run a Wordpress-Duplicator backup using Docker Compose.


# Use case

I use this to run a copy of my old Wordpress blog in case I want to make tweaks and re-import the data into my new non-wordpress site.

Starting from a zip file and installer.php generated by Wordpress Duplicator
This project can bring up a backup of your site running locally.

Ensure files are in the wp-archive

```sh
$ ls wp-archive
20171025_devstu_ed680e55e011c2356456171025215736_archive.zip  installer.php
```

Start the environment:

```sh
$ make up
```

Data Persistence:

The database is persisted across container rebuilds by mounting the MySQL directory `wp-mysql`.
However, the source of truth is the duplicator archive.

To save any changes you *must* export the site to a new duplicator archive.

For more detailed info, see the Usage section.


## Features

 - Set up Wordpress, Apache and MySQL on build
 - Modifies site urls to localhost or custom URL so links work locally.
 - Makefile for common tasks (bring up / down / set credentials etc)


# Configuration

## Image Versions:

Before running find the MySQL and PHP versions used by the Wordpress site and configure them here:

MySQL: In docker-compose.yml, change the db image to the exact MySQL/MariaDB version used to originally host the WordPress site.

PHP: In the Dockerfile, ensure FROM wordpress:phpX.X-apache matches your backup's era (e.g., php7.4-apache for older sites).


## Environment variables:


The following environment variables can be set by modifying the `docker compose.yml` file:


WordPress Container
-------------------

### Wordpress base URL links are updated to match this)
WORDPRESS_URL: 'http://localhost'

### Database connection credentials
WORDPRESS_DB_HOST: db
WORDPRESS_DB_NAME: wordpress
WORDPRESS_DB_USER: root
WORDPRESS_DB_PASSWORD: password

### Set WPD_OVERWRITE_SITE to 1 to force re-extraction from the duplicator archive
WPD_OVERWRITE_SITE: "false" 

### MySQL Container
MYSQL_DATABASE: wordpress
MYSQL_ROOT_PASSWORD: password


## Usage

Install the Duplicator plugin on your WordPress site (https://wordpress.org/plugins/duplicator/) and generate an archive. There is a video at the link above with more information on using duplicator itself.


1. Install Docker Compose.

2. Clone this repository

```sh
$ git clone [https://github.com/stuaxo/wp-duplicate-docker.git](https://github.com/stuaxo/wp-duplicate-docker.git)
```

3. Copy the duplicator archive and installer.php to the wp-archive folder.

4. Update your Configuration (see above).


Run your blog in docker:
```sh
$ make build
# or: docker compose up -d --build
```


# Make commands

Reset database and content:

```sh
$ make reset
```

Alternatively set the `WPD_OVERWRITE_SITE` environment variable to 1.


# Security
This setup is made for local development, so is not setup to be secure.


# Docker internal scripts
In the `duplicator/` folder:


## `duplicate-entrypoint.sh`
- Checks there is only one duplicator archive in wp-archive then calls `restore-duplicate`
- Runs Apache to serve the Wordpress site.


## `restore-duplicate.sh`
- Extracts the duplicator archive in `wp-archive`.
- Restores the database backup.
- Configures Wordpress with settings to run in docker.  


## Troubleshooting
If you already run a webserver such as Apache or Nginx on port 80 you will need to stop it first, 
the same applies for MariaDB or Mysql.

It's worth setting the MySQL version to the exact version used to originally host the Wordpress site.


## Limitations:
By design: changes to the duplicate site are currently not saved, this is fine for my purposes but may not be for you.
